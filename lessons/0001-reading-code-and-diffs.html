Lesson 1 · Engineering with AI

Reading Code & Diffs

Right now, when Claude changes a file, you can tell that something changed — but not always what, or whether it's the right change. This lesson gives you just enough to read a small diff and a short Python function with real understanding, using a piece of your own AutoForm project as the worked example.

Why this matters for governance. Your own MISSION.md says you stay the decision-maker over what Claude builds — reviewing changes before accepting them, not just trusting "it runs." That's not possible if you can't read what changed. This lesson is the first building block underneath that principle.

1. What a diff actually is

A diff is just a before/after comparison of a file, shown line by line. Git (and Claude Code, when it shows you changes) uses three markers:

  • - a line that was removed
  • + a line that was added
  • no marker — a context line, unchanged, shown so you know where you are

That's the whole syntax. Everything else is just reading the actual code on each line.

2. A real example from AutoForm

Your decision log (governance/08_decision_log.md, entry D007) records a real decision: block the "Submit" button in code, not just by telling the AI not to click it. Here's roughly what that change looked like as a diff, inside agents/form_agent.py: 

 def _execute_actions(page, actions):
     descriptions = []
     for act in actions:
         kind = act.get("action", "")
         if kind == "click":
             x, y = int(act["x"]), int(act["y"])
             label = act.get("label", "")
+            if _is_submit_action(label):
+                descriptions.append(
+                    f"BLOCKED — refused to click '{label}'"
+                )
+                continue
             page.mouse.click(x, y)
             descriptions.append(f"Click ({x},{y}) — {label}")

Read it the slow way, line by line, in plain English:

  • if _is_submit_action(label): — before doing anything else, ask a separate function "is this label a Submit-type button?"
  • descriptions.append(...) — if yes, record in the log that the click was refused
  • continue — skip the rest of this loop iteration entirely, meaning page.mouse.click(x, y) on the next line never runs for a submit button

That last point is the whole safety mechanism. The click physically cannot happen for a submit-labelled button, because the code returns early. No system prompt, no instruction to the AI — a structural guarantee. This is exactly the "instruction vs code" distinction your own notes/architecture.md already names.

The one question worth asking on every diff: "What can now happen that couldn't before — or what can no longer happen that could before?" For this diff: clicking a submit button can no longer happen. That's the entire point of the change, in one sentence.

3. Try it yourself

1. In a diff, what does a line starting with - mean?
Correct — removed entirely from the new version.
Not quite — a bare - means the line existed before and is gone now.
2. In the AutoForm diff above, what stops the submit click from running?
Correct — continue exits that loop step before reaching page.mouse.click.
Look again at what happens right after descriptions.append(...) in the added lines.
3. Why is this control "structural" rather than "instructional"?
Correct — even if a future prompt changed, this line of code would still block the click.
Re-read the architecture note: structural means the rule survives even if the AI drifts.

4. Read it for real

Open agents/form_agent.py in your own AutoForm project (in VS Code, or even just by asking Claude to show it to you) and find _is_submit_action, just above _execute_actions. It's six lines. Read it before scrolling further, then check yourself: 

def _is_submit_action(label: str) -> bool:
    low = label.lower().strip()
    return any(p in low for p in _SUBMIT_PATTERNS)

In plain English: take the button's label, make it lowercase and trim whitespace, then check whether any of a list of known "submit-ish" words (defined elsewhere as _SUBMIT_PATTERNS) appears inside it. If any do, it's treated as a submit action.

Ask Claude a follow-up right now, in your own words: "Show me _SUBMIT_PATTERNS in form_agent.py and explain why each word is on the list." Don't just read my answer — go get the real one and see if it matches what you'd guess.
